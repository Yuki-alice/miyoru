# 2026-11-05

## 用 m3e-canvas 做设计原型

用户需求：参考 Komikku 的设计风格，做一个「视频 + 小说 + 漫画」三合一内容 App 的设计原型，手机 + 桌面宽屏，交付形式是直接给 M3E Canvas 分享链接。

- 调研了 https://github.com/lnkiai/m3e-canvas（MIT，Next.js 16 + React 19），关键入口是 `public/agent.md`：AI 代理可以直接写设计 JSON，编码成 `#docz=` 分享链接。
- 用户发来的 `#docz=...` 链接解码后是**空白画布**（frames/groups 为空），据此作为格式起点继续填设计。
- Komikku 风格要点：Material 3 深色优先、封面驱动动态配色、书架/分类/追更、沉浸式阅读器、封面网格。
- 产出 5 个逻辑屏 × 2 宽度 = 10 frames、87 groups、112 items：首页 / 书架 / 作品详情 / 阅读器 / 播放器。手机 412×892 一行，桌面 1280×800 一行；桌面用 navRail、4 列封面网格、详情与播放器分栏、阅读器正文限宽 720dp 居中。
- 主题：purple 基准 + dynamicColor、深色显示但 bothModes 开启、emphasized + expressive motion、platform=web。
- 产品名称**未定**，画布 title 用中性占位名「内容库」，文档与页面均已如实标注。

工作区文件：
- `build_prototype.py` — 参数化生成脚本，改屏幕定义后重跑即可
- `design.json` — 设计文档（可用画布 Open project 打开）
- `prototype.html` — 一键打开原型 / 复制链接 / 屏幕说明
- `share-link.txt` — 纯链接文本

结构自检 0 错误（唯一 ID、字段类型、图标名、跳转目标）。踩坑记录：`isProject` 拒绝可选数字字段为 null；桌面组件默认宽度固定 412/380，必须显式给 size。可复用流程已沉淀为用户级技能 `m3e-canvas-prototype`。

## 原型深化（同日下午）

用户要求：导航扩为 5 个 tab 且顺序为 首页 / 书架 / 历史 / 浏览 / 更多；「浏览」承载数据源、插件订阅与站点浏览，「更多」作为 7 个子页面的路由入口（下载、分类、统计、插件商店、设置、关于、数据与存储）；详情宽屏去掉 rail 更沉浸；整体页面覆盖更全面。

- 重写 `build_prototype.py` 为声明式生成：`Flow` 垂直流式布局 + 页面 spec，一份定义自动产出手机/宽屏两版；`SCREENS` 共 17 个逻辑屏 × 2 = 34 frames、249 groups、362 items。
- 新增屏：历史、浏览、更多、数据源管理、站点浏览、下载、分类、统计、插件商店、设置、关于、数据与存储。五个主屏互相跳转闭合，更多页 7 条路由全部可达。
- 沉浸式页面（作品详情 / 阅读器 / 播放器）宽屏不显示 navRail、手机不显示 bottomNav；详情宽屏改为 topbar 全宽 1280、封面左 / 信息右 / 目录下。其余二级页宽屏保留 rail 且高亮所属主 tab。
- 画布改为槽位式布局：每个逻辑屏占 1360×2000，手机版在上、宽屏版在下成对对齐。
- 紧凑文档 85,480 字节，分享链接 15,033 字符。完整自检 0 错误、0 组件越界。
- 新踩坑：宽屏 frame 误加 `bottomNav` 会溢出 92dp；图标 `restore` 不在 material-symbols.json（换成 `settings_backup_restore`）。两条经验已补进 `m3e-canvas-prototype` 技能。


## 原型优化（同日 16:50）

用户要求：宽屏下除 5 个 tab 主屏外，其余所有子页面都不显示 rail。

- 把导航显示规则从逐屏 `nav_wide` 字段改为构建阶段集中判定 `spec["key"] in MAIN`：SCREENS 里删掉 17 处字段声明，以后新增子页面自动遵循规则。宽屏有 rail 的帧恰好 5 个（home/library/history/browse/more），其余 12 个全部沉浸。
- 去掉 rail 后布局自动切全宽：`Flow.left` 112→32、`cw` 1136→1216、topAppBar x=80/size=1200 → x=0/size=1280；所有沉浸页确认保留 `arrow_back` 返回出口，不存在孤立页。
- 结果：34 frames / 241 groups / 353 items，紧凑文档 80,810 字节，链接 14,928 字符。
- 新增水平越界自检后抓到旧 bug：手机端「站点浏览」6 个筛选 chip 横排溢出约 180dp。修法：`Flow.chips` 窄屏按每行 4 个自动换行（宽屏 8 个）。最终 0 结构错误、0 图标/跳转错误、0 垂直/水平越界。
- 工程教训：批量文本替换要逐处 `assert count == N`；`nav_wide=False` 同时出现在 `Flow.__init__` 默认参数里，直接全局替换会误伤函数签名。
- 同步更新 `prototype.html` 的标签与说明、`brief`（会随 Copy prompt 导出）以及用户级技能 `m3e-canvas-prototype`（新增水平越界、导航规则集中判定、沉浸页返回出口、替换断言四条）。
